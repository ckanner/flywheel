# JEV 执行决策与有界诊断扩展

## 目标与实施边界

用户要求将真实账号、效果和桌面验收留到后续，先完成剩余工程能力。本轮接在
PR #37 的 `4ea69cc54176d7afa36d235e6b7dc8728005a671` 后，继续使用同一个
`jev.enabled`。不恢复影子路径，不增加按动作族启用的开关，不改变默认 Provider、
模型或推理等级，不用本地 fixture 的速度推导真实收益。

本轮交付的是可执行、可恢复、可关闭的完整决策路径：

| 能力 | 已有基础 | 本轮补齐 |
| --- | --- | --- |
| 调查动作 | 精确路径读取、文本搜索、目录名字 | 明确批准的复现命令、独立副本实验、精确 HTTP 读取 |
| 失败后下一步 | 固定返修、空转升级与重规划 | 在合法修复、补证据和重规划之间采用 JEV 选择 |
| 模型／effort | 完整绑定允许集及确定性质量升级 | 在同一允许集和切换预算内采用 JEV 选择 |
| 反馈检查 | 完整冻结 gate 和结构化失败观察 | 优先选择有信息价值的已批准检查，补充下一轮反馈 |
| 可解释性 | 调查选择与证据控制记录 | 实验结果、失败决策、实际效果、基线及未知状态的桌面展示 |

Auto 继续由 Go 校验 Quick／Full 资格。Plan、最终验收、独立 Review／Judge、
权限和远端交付授权不由 JEV 放行。没有需要选择的分支时直接执行原路径；明确的
小修复不因打开 JEV 固定增加模型阶段。

## 调查动作契约

### 有界命令与副本实验

`run_command` 冻结 exact argv、批准输入文件、环境变量名、超时、预期退出码和
`execution-boundary: host-process`。宿主根据原任务授权准备具体命令，JEV 只能
选择已存在的 action ID，不能拼接参数、扩大输入或要求更多凭据。

引擎把精确批准的普通文件复制到私有临时目录，在副本中通过受管进程执行。不隐式
运行 shell，不递归扩大目录的读取授权；符号链接、特殊文件、越界路径及超限输入
拒绝。需要解释器时明确出现在已批准 argv 中。凭据只记录环境变量名，输出脱敏。

副本隔离保护原输入和普通相对路径写入，但 `host-process` 不是 OS 沙箱。命令拥有
主机用户实际可用的能力，无法仅凭工作目录阻止访问其他路径或网络。需要强隔离的
任务应批准调用实际容器／沙箱入口，不能把 worktree 或副本描述为强隔离证明。

动作受全局 deadline、动作数、单次超时和输出上限限制；取消结束整个进程组并确认
收尾。回执记录退出、信号、超时、取消、输入身份、临时目录与清理结果。未知动作
或清理未确认保留现场并阻断，不自动重跑。预期非零退出可以记录复现证据，但不能
被当作授权提前结束调查的成功观察。

### 外部只读查询

`http_read` 只接受明确批准的 GET／HEAD 与精确 URL，冻结预期状态、超时和响应
上限。要求 HTTPS（本地 loopback fixture 可用 HTTP），禁止 URL userinfo、
fragment、重定向和环境代理；凭据由 `headers-env` 引用环境变量名。HTTP 方法
并不证明对端无副作用，地址与请求仍须属于原任务授权。

请求和返回采用同一动作意图／回执恢复协议；超时、异常状态、响应截断或未知请求
不能成为成功取证／提前报告依据。响应是外部数据，不能改变工作流权限或预算。

## 执行中的决策边界

只有已经确认结束的执行／验证／评审失败才形成下一步候选。Go 根据当前 packet、
失败观察、已尝试路径、剩余尝试、工作流和模型允许集生成动作及确定性基线。

| 候选 | 前提与实际效果 |
| --- | --- |
| 继续局部修复 | 原边界及剩余尝试允许；继续原 Execute 闭环 |
| 补充反馈证据 | 已批准检查有明确参数和预算；运行并保存真实结果，再交回执行者 |
| 请求重规划 | 原任务允许且还有规划次数；走既有受限 Plan；Quick 先持久化升级 |
| 选择模型／effort | 在冻结的完整 execution-policy 绑定允许集内；消耗同一切换次数并冷启动 |

身份不可靠、动作终态未知、边界违规、权限不足或预算耗尽，均不能通过 JEV 变成
“再试一次”。AUTH／QUOTA 等渠道错误使用既有错误分类，不冒充质量问题，也不
让 JEV 扩大费用渠道。反馈检查是额外事实，不替代最终完整 gate，不减少检查集合。

没有配置多个合法执行绑定时继续使用原模型；一个 JEV 开关不能替用户生成模型
授权。已有允许集属于实际资源与权限声明，不是新增 JEV 功能开关。

Packet 可选 `feedback-checks`（最多八项），用于声明不同于完整 L1 的短诊断命令，
结构沿用 GateEntry 的 cmd／script 与 expect，另用 `purpose`（最多 160 字符）
描述可区分的原因。用途作为已批准任务摘要供 JEV 比较，不发送原命令或把日志
伪装成结构化事实。缺少用途的短检查仍供执行者参考，不进入定向决策候选；JEV
也可复查有可靠失败观察的 L1 检查。补充检查沿用冻结验证环境、超时和清理规则，不
缩减最终 gate。候选 ID 区分 feedback 与 L1 recheck，不能混用数组下标。

## 持久化、预算和并发

任务账本保存冻结策略、决策快照、原派发时间、请求回执、采用原因和动作绑定。
调用前持久化意图并预留次数，返回后重核当前总开关、限制与目标；采用前再次核对
候选、契约、观察和允许动作。选择消费与待执行效果必须通过同一 CAS 提交。

未知 JEV 请求只读恢复，不重发；实际动作未知仍阻断。重复恢复不重复切换模型、
派发检查、启动 Plan 或记账。调查移交实现继续累计调用与已知／未知用量，切阶段、
packet、模型或恢复不能重置总上限。并行 worker 的决策由任务所有者协调，不能各自
复制一份调用额度；不得因新决策模块绕过既有 lease、取消与共同候选复验。

普通任务只用 `jev.enabled`；开发用在线 evaluation 继续强制 advisory，离线 replay
继续不联网。调用方只开放自己具有真实执行器的动作族，协议枚举本身不提供执行权。

## 接入与验证

Task／New／Run 继续承担准备、调用和结果翻译，不能把内部循环搬到 skill。桌面
沿用单开关，展示真实动作与效果、原因、失败／未知、累计预算和清理状态。契约、
schema、当前设计、双语指南、技能和测试随实现同步。

本轮执行工程门禁：逐函数 Go 覆盖率、失败与恢复行为、race、插件行为、跨进程
Provider 桥接，以及真实本地子进程／HTTP fixtures。用例验证分支实际执行和关闭
回到基线，不只检查 prompt 或 JSON 枚举。

按用户最新要求，真实 JEV／模型任务、Mac 桌面效果、耗时／token／质量配对验收
留到后续。P5 的 ready queue、预热和进一步流水化仍按原方案“收益成立才实施”；
本轮不会在缺少瓶颈数据时将它们变成强制默认。合并、发行与用户安装是独立交付
动作，不能把源代码提交称为已发布或已在用户机器生效。
