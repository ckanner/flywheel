# 流程工作台交互实现

用户已审阅并批准画布优先的交互稿。本轮改造 DSH 插件的实际界面，不替换 Go 控制面，不把演示中的任务、状态、模型能力或路径带进产品。

## 界面与操作

- 原生 `conversation.view` 仍排在统计之后。紧凑任务标题、真实分支与只读位置构成上下文；流程、运行记录、配置为三个固定入口。
- 横向画布使用整个插件内容宽度；任务总览按阶段分组，点击打开局部节点详情，展开任务进入独立子图。节点详情是视图内部区域，不注册第二个全局 DSH 侧栏。关闭恢复画布空间。
- 节点详情分进展、会话、配置，动作紧邻所选节点。单步、人工继续、接管、远端交付沿用现有接口的 revision、会话、HEAD 与确认机制。未确认调用只允许核对，不推测成功。
- 画布提供平移、缩放、适合视图、定位当前任务、可键盘操作的节点以及窄窗口列表。新快照保留视角和选择；任务切换清空旧节点选择。单阶段优先展示真实单阶段结果。
- 配置仅在打开页面或切换作用域后自动读取一次。普通保存一次点击；重置先审阅预览。切换作用域、重新读取或重置不得悄悄丢失草稿；失败保留草稿，保存结果未知必须重新核对。
- 配置按工作方式、模型分配、预算与重试、JEV 分组。串行不展示无效并发控件；毫秒以分钟/秒编辑并精确转换。无修改不展示禁用的保存按钮。
- 实际配置接口提供文件级 Source，并不提供逐字段继承来源。项目配置文件是完整配置，新文件以安装模板创建；不得照搬设计稿中的“每个未修改字段继承全局”示意。配置优先级和真实来源在界面明确说明。
- JEV 默认关闭，保持影子评估语义。模型目录未接入时不虚构“已验证模型”；沿用已配置标识、安装模板预设和自定义输入，运行时仍由后端校验。
- 运行记录采用选择列表与详情，保持 Run ID、候选、条件及缺失用量的边界。选择历史记录不启动任务，打开画布重新查询当前状态。

## 验证

DSH 构建/行为测试与旧宿主检查、三个 Node 桥接检查；增加自动读取、草稿切换、失败/未知保存、数值换算、节点选择与真实请求身份、子图和单阶段状态的行为测试。浏览器验证实际构建产物的浅色/深色、宽窄布局及关键操作路径。真实 Provider 推理、npm 发行与桌面安装分别验收。
