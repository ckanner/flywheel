# 任务发现和单阶段画布修复

## 已复现的问题

loveops 的目标会话加载了两次 flywheel-task，但没有调用 flywheel_launch。之后在 Bash 中四次运行 verify/review；最后 Review pass，整个任务仍 pending。旧视图只消费专用工具和控制命令，未获得任务关联；两个空路径框显示了示例占位符，所有任务按钮禁用。上轮已通过只读 status 为该会话恢复真实任务关联。

## 实施

1. Go 运行登记增加可选 hostSessionId，从 DSH 的公开 DSH_SESSION_ID 读取有界标识。插件控制入口显式传入自身 session.id 并清除无关继承值。该标识只用于发现，不能授予控制权、继承父会话状态或替代租约／revision 检查；不向 Provider 或验收子进程扩散。
2. 画布独立读取已有运行索引，按当前 session.id 匹配并按任务去重；不扫描磁盘。没有手动选择、没有未确认操作且本会话只有一个任务时，自动选择并请求 status。多任务、无归属历史任务显示明确选择。当前选择和异步读写不被目录刷新覆盖；晚到的旧会话响应不能污染新视图。
3. 顶部显示当前任务与最近阶段；彻底删除两个路径输入框。任务和工作区位置由会话／运行记录自动取得，取得后才显示为只读信息；没有值不显示空字段。无任务时提供任务选择与刷新列表。准备但尚未运行的任务由 flywheel-new 的只读 status 关联，用户无需复制路径。
4. run.kind 和 control.kind 一致的单阶段运行显示本次阶段及回执。Review 视图默认展示 L1 → Review，并可展开完整流程；继续整个流程不作为默认主按钮。历史证据和当前 snapshot 状态分别标注，未完成的整体验收／Git 交付不伪装完成。
5. 单阶段技能执行后查询 flywheel_control status 以显式关联，失败／未知仍保留原路径核对。flywheel-task 不把加载成功说成启动成功；用户明确选择此入口时，文档任务同样可建立可验收契约，若仅调研／方案则明确说明未启动。

## 验证边界

使用真实宿主环境约定、Go 运行索引、原生 renderer 行为测试验证归属和恢复；覆盖多会话、旧记录、并发读取、未确认操作和单阶段失败。完整 Go 逐函数 100%、插件与三组桥接、双语文档继续适用。不会启动用户的 SIP 任务或改其账本，不重启存在其他活动任务的 DSH；源码、开发预览与正式安装分别报告。
