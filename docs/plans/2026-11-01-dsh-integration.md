# DSH 集成与可靠执行实施计划

## 已确认范围

- 基线：`ckanner/flywheel@0a464473f590e6717a88d7ea885290df7339c7a3`。
- Go 引擎拥有任务状态、契约、预算、worktree、验收和完成判定。
- DSH Mac 桌面负责入口、原生模型执行、控制和展示；不依赖尚未进入当前桌面包的 OAR/Forge。
- DeepSeek 仅 Flash；Kimi 直接 CLI，不使用 ACP；GPT 原生 DSH 和 Codex 是不同执行后端。
- Codex Pro adapter 的外部仓库由另一 session 处理。本轮提供消费契约，不在该仓库并行修改。
- 保留 100% statement 门禁。测试验证公共行为、真实 Git/进程与协议失败，不以 mock 内部调用刷覆盖率。
- 具名模型 profiles、复杂自动路由与大规模并行是后续增强；本轮修复已有配置未生效的问题。

## 关键不变量

1. `completed` 对应的最终 Git tree 必须是通过检查和评审的候选 tree。
2. 提交失败、无法持久化、合并失败不能完成；若代码已确认保存和合并，仅清理失败可记录 completed，但必须保留工作区引用、cleanup-error 与恢复线索。
3. 只有当前 Spec/packet/检查配置/候选 tree 的证据可以用于推进状态。
4. 实现者的自报不代替确定性验收；评审独立会话且不得修改候选产物。
5. 取消与超时管理本次拥有的进程组，不影响其他任务；已观测到的清理错误不得当成交付成功。stop 的 stopped 表示引擎生命周期结束，不等同于任意逃逸进程均已清理。
6. 新模型/工具配置必须实际生效；不支持的参数与未知用量明确呈现。
7. 契约、运行状态和预算由引擎维护；插件不直接编辑 state.json。

离线测试不调用付费模型。目标版本通过文档/源码核对与模拟协议验证；真实模型、订阅账号、用户 Mac 桌面安装和视觉操作另记为 live 验证，不用离线通过冒充。

## 实现过程中确认的边界

- 规划只直接改任务目录内 Spec/packet。目录外验收 oracle 和运行配置的改动会保留文件并停止自动提交；它们需要显式修订任务。
- 契约集合变化同步所有保留候选工作区；相邻 packet 的修订也不能留下旧副本。已关闭里程碑被重开后会重新访问，每次 run 同一里程碑最多访问三次。
- Git 提交 hook 不能使已加载契约、已测试候选和实际保存的 tree 脱节；提交后仍须核验。
- 历史已跟踪 done-report 在工作区收集后恢复调用前版本；只有原来未跟踪的临时报告被删除。
- 从任务子目录启动 CLI 时，执行根规范化为 Git 仓库根；手动重执行完成单元会重新打开里程碑。
- 非 Git 目录可用于部分步骤演练，但不能报告完成的 Git 交付。
- 未发布版本不覆盖现有配置。采用新的 Flash/Kimi/GPT 默认表需要用户比较并迁移配置。
