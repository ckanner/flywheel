## 2. 本轮实际验证的行为

### 持久化和恢复

- 失败的 commit hook、index-only 篡改、工作区与 index 同时被 hook 修改、账本 hook 修改源码或报告，都不能推进 completed。
- 单元代码提交、快进合并、主账本提交及任务最终完成前都有持久化检查。非 Git 目录不能产生完成交付。
- 非账本 candidate 的 assume-unchanged、skip-worktree、有效 clean/process filter 与 working-tree-encoding 被明确拒绝，不自动修改用户 Git 设置。
- 合并或提交失败保留实现 WIP、分支和报告；已确认交付后的单纯清理失败保留 worktree 引用及 `cleanup-error`。
- 报告先在候选工作区生成，再校验并归档。历史 tracked 报告恢复到调用前 HEAD 的内容与模式；仅原来未跟踪的临时报告删除。
- 旧候选、done-report、契约或检查配置被修改后不能复用旧绿灯；失效证据保存在历史中。
- 从任务子目录启动会规范化为 Git 根；手动重执行已完成单元会重新打开里程碑，并能继续完成与安全清理。

### 契约与验证

- planner 已自行提交、本轮没有新提交 SHA 时仍同步保留工作区；修改相邻 packet 也同步整份契约目录，保留未提交实现。
- planner 越权修改代码、目录外 oracle 或运行配置时拒绝自动提交并保留文件。提交 hook 导致契约漂移也拒绝继续。
- 跨重启重新核对契约指纹。旧版本没有指纹的 completed 状态保守重验；合法后续单元的普通源码变化不被误当成旧单元的契约修订。
- 新 packet 或修订会重开相关里程碑，调度器动态回访；同一 run 的同一里程碑最多访问三次，避免反复重开导致无限调用。
- L1、L2/L3 与独立 Review/Judge 都检查前后候选身份；验证命令或评审修改候选，不能把绿灯套在新内容上。
- verification-gap 返回 Plan 后先复验；加强后的检查失败会回到执行，并将实际命令、退出信息和评审理由放入下一轮反馈。
- 普通单测与回归可修改；受保护验收和契约不可由 executor 改动。提示词带入真实保护路径／正则。

### 模型进程与计量

- Kimi 使用 CLI print/stream-json，不用 ACP；验证显式 session、cwd、thinking、取消、错误事件、尾行以及可靠终态。未知 usage 保持未知。
- Codex CLI 使用显式模型和角色权限；只有完整 `turn.completed`、对应文本和可靠物理退出共同成立才成功。空、部分或非法 usage 不伪装成已知零。
- DSH worker 核对 request/session/cwd/provider/model/effort/权限回执；只有完整沙箱及可证明的 SDK 终态才能提交结果。idle、token 截断、错帧、错误权限和强制关闭不判成功。
- stop 不信任 PID 数字，而用每次运行的随机 token 发请求；等待 lifetime lease 释放后再 CAS 更新状态。旧 PID、旧请求、换代、启动窗口、超时与请求写失败均有回归。
- 超时、取消、信号及清理失败不因退出码恰好符合预期而通过；缺陷注入的不完整执行不能冒充成功发现缺陷。
- metrics 写失败停止后续模型调用；unknown usage/cost 单独计数，汇总只表示已知下限。hard token budget 无法验证未知用量时停止。

## 3. DSH 宿主与实机边界

接口目标固定为已核对的 DSH Mac `0.2.1-rc.5`。本轮在官方 npm rc.5 上实际验证了 Host command/tool 注册、SDK 初始化与关闭；在当前 Linux 环境，原生沙箱不可用时 doctor 正确拒绝，且没有发送模型 prompt。

以下仍需在用户 Mac 上验证，不能用交叉编译或 fake SDK 代替：

1. About 中的具体 DSH 版本、CPU 架构、桌面命令入口；插件的实际安装和界面渲染。
2. SDK profile 中 DeepSeek／ChatGPT adapter 的实际注册与授权；桌面 profile 不会自动成为 SDK profile。
3. Seatbelt 与文件权限探针；Kimi CLI 的会话恢复和取消。Kimi print 模式不提供本适配器可宣称的 OS 级工作区沙箱。
4. 使用账号可用模型完成一个小任务，检查 done-report、验收、提交、暂停／恢复及停止，记录真实延迟、速率、额度和 usage。
5. 异常断电／应用退出之后的真实恢复。`stopped` 代表引擎生命周期结束，不是任意脱离进程组的进程已被全局清理的证明；清理错误仍须查看证据。

本轮没有真实模型性能基准，不给出未经测量的速度、成本节省比例或质量排名。已有控制机制包括确定性门禁前置、有效证据复用、有界重试、里程碑级终验、明确渠道与未知用量记账。
