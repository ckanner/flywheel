# DSH 0.2.2-rc.1 兼容复核（0.28.4）

## 来源和故障

用户已将桌面更新到 0.2.2-rc.1。已发布 Flywheel 0.28.3 将 engines.dsh 精确锁在 0.2.1-rc.5；新版宿主拒绝加载桌面插件，SDK 也禁用了同包的 flywheel-worker-policy 行。无推理探测复现 INVALID_REQUEST，原始诊断明确说明策略模块被版本门禁禁用；没有发送模型 prompt。

核对的上游源码：rc.5 `b830ec950faba0a46dda564be3e2d854afed94f1`；rc.1 `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`。检查 engines.dsh 的优先级与 includePrerelease 规则、commands/tools 注册、会话当前目录、客户端槽位／StoreHandle／renderer、SDK 方法及事件／关闭协议、shell／sandbox／approval。所用公共签名仍可用。两版 effectivePolicy 均为私有，overrideOf 为公开；本次回执改为读取显式写入后的公开 overrideOf。

准入后实机进一步复现真正的生命周期变化：三种权限模式均返回 `cannot append before session/created completes`。新版 Session 公告只读；两版 AgentFactory 均在公告结束后串行等待公开 agent/created，再释放模型工作。本次把权限事件移至该阶段，继续在任何 prompt 之前要求完整权限回执。

## 修复与门禁

统一六包 0.28.4。DSH 声明是两个已核对精确版本的并集，未知未来版本仍不放行；同步 Cordis 与 host peer 范围。主测试使用新版真实发布的 renderer，锁定旧 renderer 的隔离 fixture 再对同一构建运行生命周期测试。测试专用 MIT fixture 固定新版宿主真实兼容性检查器，验证没有版本豁免时的接受和拒绝。

不修改 DSH 的版本豁免或强制规则。保留已迁移的账号全局配置；迁移后 SHA-256 应仍为 `86a56fb012d669263c5e958c14a5effbfdade122167f235d2cd39b21000bdddb`。当前还存在其他旧官方插件的兼容警告，本轮不修改其配置。

本轮实际结果（macOS arm64；测试 Node 24.22.1／npm 12.2.1，目标 worker Node 26.12.1，官方桌面 CLI DSH 0.2.2-rc.1）：

- Go/Node DSH 与 Codex Pro 离线跨进程桥接两项通过（18.117 秒）。

- 新候选源 worker 在实际 rc.1 的四项配置 SDK 探测均通过；read-only、workspace-write、danger-full-access 三种真实 shell／权限回执和正常收尾分别通过。全部为 doctor，无模型 prompt。
- 全局账号配置 SHA-256 保持不变。Go、templates、skills 源码相对 0.28.3 无差异；本轮没有新的 Go 改动。

六包 0.28.4 开发候选已隔离构建，原 tarball 的真实安装测试 7/7 通过（9.530 秒）；另对打包后的插件 manifest 使用新版宿主原始检查器验证，两版均被接受且没有版本豁免。开发候选标记 dirty，不用于上传；批准提交后在精确干净 tag 上构建正式候选并复测。本记录不声明 npm 已发布、桌面已恢复、模型账号已验证或未知版本可运行。后续发行必须绑定干净源码、精确 tag 与同一候选；不覆盖已发布的 0.28.3。
