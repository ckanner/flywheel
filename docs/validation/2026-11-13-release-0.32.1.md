# 0.32.1：DSH 兼容系列范围与发行

用户在将桌面升级到 DSH 0.2.2-rc.3 后要求检查并修复 Flywheel，明确要求结束逐 rc
修改版本白名单的方式。本次沿用已授权的发布与安装流程。

## 原因与修复

原生插件详情确认 0.32.0 被 `engines.dsh` 的精确白名单标为未运行。四项 SDK 探测
也失败；直接读取无推理 worker 回执，确认 SDK 同样拒绝加载该包的权限确认组件，
随后因缺少 `policy.json` 返回 TRANSPORT。没有通过版本豁免绕过此检查。

0.32.1 将宿主范围改为 `>=0.2.1-rc.5 <0.3.0-0`。DSH 判断范围时包含预发布版本，
因此 0.2 系列后续 rc／补丁可自动准入；0.3 系列及其预发布版保持拒绝。
宿主提供的 optional DSH peer 范围同时覆盖已有预发布系列，测试依赖锁定真实发布的
0.2.2-rc.3。运行时所需服务、权限回执、会话身份与清理检查均未删除。

测试中的上游兼容检查实现与 DSH rc.3 源码
`38a6a5c965aa99ab525161efb7cc5cf1fe62fced` 比对未发生变化。版本范围测试覆盖后续 rc、
正式版及补丁版准入、最低版本以下和下一 minor 预发布版拒绝；同时验证 npm 的
默认 prerelease 匹配规则。范围是兼容策略，不代表所有未来宿主均已实测。

- 初次更新测试锁文件遇到 rc.2/rc.3 传递 peer 冲突；移除旧 DSH 测试依赖解析记录后
  重新正常解析，没有使用 force 或 legacy-peer-deps。非 DSH 锁条目没有变化。
- 首包与插件包曾发生 npm 认证会话失效（authId 404）。实际 registry 核对后续发，
  未更换候选。首包被接受后超过 180 秒尚不可见，发行器按规则停止；其余无依赖
  平台包上传使用相同源码、标签、候选及 integrity 前置检查，四个平台全部公开并
  核对后才恢复标准发行器上传插件和入口包。
- [发布 Actions 43469804204](https://github.com/ckanner/flywheel/actions/runs/43469804204)
  和 [CI 43469804576](https://github.com/ckanner/flywheel/actions/runs/43469804576) 未通过。
  发布 preflight 没有执行步骤；annotation 指明账号付款或 spending limit 问题。
  本机验证不冒充 Actions 通过。
- SDK 探测 `inferenceTested:false`；账号授权／额度、真实模型质量、全部任务恢复场景
  和未来 DSH 版本的实际接口兼容性不由此建立。
