## 2. P3 的实际边界

worker v3 传递 lifecycle v1，原始 machine 请求/回执保持 protocol 1。Go 先保存 intent，并在 ACK 前 fsync 检查点、状态和必要候选证据；上游 supervisor 在发送 terminal/cleanup-confirmed 前先持久化完整原始回执。terminal ACK 丢失不改写已发生结果。

Codex 能在 turn/start 前交出实际 thread/configuration，由 Go 完整检查 sandboxPolicy 后确认。Claude init 在 prompt 之后出现，因此显式不具备预派发 thread-ready，也不发明 native turn ID；它仍等待派发前 intent/possible ACK。DSH/Kimi 维持各自既有能力，不冒充这些新接口。

只读恢复只读取原 request/run/journal，不发 prompt、不启动 CLI、不查全局历史。成功回执必须同时具有原 Go cleanup 检查点中的候选／guard／report，才可继续业务；缺少原候选证明时可对账可信用量，但仍阻断。pending 不证明进程存活，supervisor 也丢失时不重放。

usage 从 unknown 转为 known 通过同调用 correction，保留原 provider、日期和 lifetime；不重复 call 或 token，不复活已淘汰日桶。metrics 的新行与已有行重试都验证文件/目录同步，CAS 失败不重复追加。

实际故障测试包括：拒绝 intent/possible ACK、坏或抢先 ACK、pending ACK 期间 SIGINT/TERM/HUP、worker 整个进程组 SIGKILL、supervisor 本身 SIGKILL、终态通知丢失、重复只读查询、坏摘要/错身份/路径所有权、状态与 metrics 持久化失败。所有执行/清理未知仍阻断。

## 3. P4 实现与完整离线对照

可按 Plan、Execute、Review、Judge、judge-panel 覆盖 fresh/scoped。三种质量阈值分别基于已确认 turn、Execute 候选不变、完整单次 input；默认均关闭。重建交接当前权威材料，不引入未计量的模型压缩，不继承另一角色私有 transcript，不清空任务预算或 attempts。

固定 corpus 实现纯函数 `compactRanges`，有独立冻结 oracle 验证输出与输入不变性。评估器隔离 clone、固定模型/effort/权限/配置身份，轮换三种策略的次序并重复。场景根据实际状态和用量判断，不凭标签算成功。

## 4. 真实账号 admission：有执行尝试，无效果结论

使用官方 `codex 0.167.0`、既有 ChatGPT 登录、`gpt-6.1-sol/high`、role-based（Execute 请求 workspace-write），通过最终 Go、worker 与公开 0.9.0 API 运行实际 evaluator。未复制 token、改变 managed 权限、切换认证渠道或用 fixture 代替此次模型路径。

仅运行 1 trial／1 Execute invocation，约 33.349 秒后 Go exit 3、任务 escalated。`thread/start` 没有在原生/Go 时限内返回，取消后 receipt 的 failure 为 thread-start/aborted；dispatch=not-dispatched、cleanup.confirmed=true。没有收到任何 lifecycle frame，所以没有虚构 early checkpoint。外层超时/取消使 outcome 保守保持 unknown，状态 blocked，评估器立即停止，不继续任何其他策略或场景。

原生 usage unknown；Go 只能依据确认未派发归一化为零用量，这不构成模型成本测量。质量、遗漏与回归字段均 null，无法形成有效配对。已有原生登录和 model catalog 不证明成功推理；此环境没有产生可用于质量、缓存或耗时比较的模型结果。

此前单独 admission 还观察到 full-access 被 managed requirements 拒绝，以及允许的 workspace-write thread/start 超时。未绕过环境约束。真实 P4 验收仍需可完成模型执行的原生环境；保持默认阈值关闭，不能声称模型节省比例或某策略优于其他策略。
