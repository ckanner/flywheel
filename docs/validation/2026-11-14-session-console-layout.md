# 会话工作台布局与配置编辑修复

- 基线：`fa4c408a2a602136a1168378fdafc1046ed21671`。
- 分支：`codex/session-console-layout`；本记录针对未发布工作树，不代表发行或安装。
- 范围：任务标题和标识、顶部位置资料、流程工具栏和单阶段结果、设置导航与阶段模型编辑。

## 实现与自审

- `taskTitle` 来自 Go 契约解析的 Spec.title；损坏或缺失 Spec 只省略显示标题，不阻断状态／停止。客户端校验可选字符串类型，旧引擎回退为“当前关联任务”，slug 单独显示。
- 未确认操作锁定原任务位置，不采用后来关联的路径。设置页只隐藏任务头部，不卸载任务关联逻辑；本会话关联更新仍然生效。项目／任务路径在头部，执行 Worktree 保持节点级事实。
- 默认展示完整任务；单阶段结果采用紧凑列表，工具栏区分本次结果与整体交付，不改变引擎完成状态和后续阶段授权。
- 五个设置栏目连续排列；内容靠近导航，保存栏与表单对齐。使用宿主实际公开的视口／输入区高度变量，保留旧宿主尺寸回退，不修改宿主 DOM。
- 阶段绑定编辑直接进入同一份配置草稿，唯一写入入口是底部“保存修改”。返回列表保留修改；撤销、作用域切换、失败与未知保存仍服从已有 revision 检查。
- 自审发现直接编辑账号渠道会留下逐字输入的中间渠道，已改为保存时只登记被修改绑定的最终渠道，新增测试覆盖；不修改未编辑配置、默认模型或权限。

## 初次检查与限制

初次插件检查使用了旧 node_modules（Codex 0.9.0、Claude 0.4.0），与锁定的 0.10.0／0.5.0 不一致，后端检查失败；按锁文件重装后完整检查通过。1 秒命令故障测试还两次出现新建可执行 fixture 未记录 start 就超时的失败（其中一次与 Go 全量检查并行），隔离运行通过。产品仍将结果标为 unknown 并阻止重复启动；不能把首次失败改记为通过。测试现改为使用现成的 /bin/sh 执行工作目录内的 control 脚本，避免把新建文件首次执行的启动延迟混入该 post-dispatch 检查；保留 1 秒超时、四种故障、精确 start/status 日志和未知结果阻断断言。新夹具连续三次隔离检查通过，最终完整复核结果见上方；不据此推断系统层启动延迟的具体原因。

新增 Spec 测试最初错误地假设 spec-version=999 不符合 schema；现行 schema 接受正整数版本。已改用确实无效的数组 title 验证拒绝路径，没有更改 schema 或削弱校验。第一次已失败的 Go 全量运行已终止，避免与最终运行争用。
