# JEV 决策

[文档目录](../README.zh-CN.md) · [English](../en/jev.md) · 简体中文

Flywheel 只有一个 JEV 开关：**启用 JEV**（`jev.enabled`），默认关闭。
开启后，所有已支持的 JEV 决策点自动参与流程，不再分别设置影子、建议、采用或
分功能开关。
分发配置使用 `backend: "subscription"` 与 `hydrogen-local`：通过原生 Antigravity
CLI 调用 medium 思考等级的 Gemini 4 Hydrogen。JEV 继续表示 Flywheel 的有界决策
机制；这个后端不请求另外计费的 System One API。

## 配置一次，继续使用原来的入口

桌面进入 **Flywheel → 设置 → JEV**，选择需要的全局或项目范围。打开**启用 JEV**，
确认订阅模型配置，再点击**保存修改**。开关先修改草稿，保存后才启用；编辑和保存
都不调用模型，也不证明账号已经获得访问权。高级字段限定超时、调用次数、阈值和
发送数据类别。

等价配置片段：

```json
{
  "jev": {
    "enabled": true,
    "backend": "subscription",
    "profile": "hydrogen-local",
    "timeout-ms": 30000,
    "max-calls": 8,
    "min-applicability": 0.8,
    "min-choice": 0.6,
    "allowed-data": ["task-summary", "diagnostic-facts", "source"]
  }
}
```

`profile` 引用同一配置里的具名模型配置。Go 冻结名称、harness、channel、完整模型
slug 和 effort。这里只接受不带 native child profile 的 Antigravity 绑定：适配器须
独立核对原生初始化里的工具列表为空，才允许返回有界答案。即使实现阶段使用 full-access，
这个请求也使用新会话、evidence-only 权限、受管进程回收与 subscription-only 策略。
原生 CLI 会保存会话历史；这里不承诺零存储或 OS sandbox。该请求没有文件读取、
诊断命令或执行所选动作的工具。

订阅 JEV 对象不填写 `endpoint`、`model`、`key-env`。模型和 effort 来自具名配置；
订阅登录及原生额外用量控制由适配器核对，不自动切 API 或 credits。确认未派发时
沿用确定性基线；可能派发且尚未确认回收时，必须先核对，才能继续任务。已有记录保留
实际原因；实施任务可能在建立首个决策账本前就不满足前提。

配置按**任务 → 项目 → 全局 → 内嵌表选择一份完整文件**，不跨文件深合并。项目
配置中的关闭会覆盖全局开启。通过 `config inspect --cwd <项目> --task-dir <任务>
--json` 查看实际配置来源；详见[配置参考](configuration.md)。

配置好以后照常使用：

- **Task**：从目标准备并运行已授权的调查或实施。Go 自动解析 JEV 策略，宿主不再手写决策模式。
- **New**：登记调查契约，或运行实现方案设计/独立审查并停下等用户批准精确版本。见[方案设计与审查](reviewed-planning.md)。
- **Run**：在原目录启动或恢复已准备的调查或实现任务。
- **Auto、Quick、Full**：仍是实现工作流策略；适用资格、验收和 review 由 Go 执行。

## 一个开关控制哪些路径

| 决策点 | 开启 JEV | 关闭 JEV |
| --- | --- | --- |
| 下一项取证动作 | 有不确定性时，在已批准的读取、搜索、目录列举、诊断命令与 HTTP 查询中选择 | 原有确定性顺序 |
| 重复取证 | 通过绑定实际观察的控制选项，跳过已经取证的假设所对应的冗余动作 | 保留原动作集 |
| 是否进入报告 | 满足引擎证据前提时，可以提前结束收集 | 按原动作、时间、输出预算结束 |
| 首次实施模型与协作方式 | 首轮 Execute 派发前，从通过资格检查的完整配置中选择一次 | 使用该 route 的 initial／原固定绑定 |
| 已确认失败后的下一步 | 在合法的局部修复、反馈检查、重新规划候选中选择 | 原有有界返修与升级规则 |
| 模型／推理等级选择 | 在已批准的完整执行绑定候选中选择，并记录实际切换 | 原有固定绑定与确定性升级／渠道后备 |
| 反馈检查优先级 | 优先选择一个已批准的检查补充事实，再继续有界执行 | 原有反馈与验收顺序 |
| 显式在线评估 | 服从同一总开关、目标和配置边界 | 在创建评估账本或请求前拒绝 |
| 已有记录的离线回放 | 本地读取和解析，不调用模型 | 仍可查看，不调用模型 |

开启所有已支持的决策点，不等于每个任务都增加一次 JEV 调用。单一合法动作和
确定性选择直接执行。数据范围不允许、硬预算无法可靠约束单次消耗、次数耗尽、
适用性不足、服务错误或响应非法时，在确认原生进程回收后继续基线路径；已形成的决策／请求记录保留
实际原因，记录前的前置条件不足不代表会新建跳过回执。Auto 仍按 Go 的契约
资格选择 Quick／Full；不为每次入口增加一次 JEV 分类请求。

提前结束和跳过动作只决定如何收集证据，不证明根因成立。Go 保存决策、观察和
动作的具体绑定；分析者仍须提交覆盖全部假设的报告，引用真实观察并说明不确定性。
没有结论仍是 inconclusive。后续修复须沿用原来的授权范围，完成实现、review 和
验证流程。详见[调查指南](investigation.md)。

## 首次实施的模型与协作选择

新订阅默认配置包含每条 route 的 `execution-policy` 候选，初始模型仍见[模型策略](model-policy.md)。默认 `quality-order:[]`、`max-switches:2`：关闭 JEV 保持初始绑定；开启后，首轮 Execute 在实际业务调用前可以选择另一个候选。已有自定义配置未声明执行策略时保持固定路由，开关不凭空生成模型。

Go 先核对未决调用、执行授权、预算和已审契约，再筛选候选。图片任务只保留有实际图片传输能力的绑定。Swarm 只在 Full、无图片且具有合法 `collaboration` 分工契约时可选；单点 Quick 任务不会自动展开。Orchestrator 是固定配置，`thinking:""`，不增加虚构的 high/xhigh 档位。候选说明包含模型、effort、原生 profile、协作方式和已知限制。

有多个合法选项才调用 JEV，输入是目标、route、已批准范围、验收、分工和预算事实；不读取实时订阅余额，也不声称已测得模型成功率。结果只能是一个 action ID。返回后 Go 复核配置、候选与总开关，记录实际绑定变化；换 effort 或原生模式同样冷启动。首次选择使用 Snapshot v3，旧调查 v1 与失败 v2 保持兼容。

首轮选择每 packet 只记录一次，与调查和失败调整共用累计调用上限；重启、并行 packet、返修和切换模型都不会重置预算。已有 pending／unknown 记录只核对原请求，不重发提示词。请求失败且清理确认后回到初始基线，清理不明则阻断。JEV 选择 Swarm 仍由 Go 启动实际执行，JEV 自身保持无工具、无子任务。

## 失败后的下一步与模型选择

引擎先确认上一轮调用已结束、结果已消费、候选与失败证据可核对，并检查剩余尝试
次数和预算，再生成候选。JEV 返回具体 action ID；Go 复核身份和当前开关后，原子
保存选择与效果。现有失败上限、Quick → Full 单向升级、完整验收和独立 Review
仍然成立；JEV 不能把未知执行结果解释成失败后重新调用。

| 动作 | 实际效果 | 前提 |
| --- | --- | --- |
| `repair` | 在原 packet 范围内继续局部修复 | 还有合法的执行尝试与预算 |
| `feedback-N` | 执行契约 `feedback-checks` 中的一项短反馈检查，把物理结果交给下一轮 | 检查已明确批准并有 `purpose` 用途说明；不能由模型新建或修改命令 |
| `recheck-N` | 重新执行一项已经失败且结果完整的 L1 检查，取得最新反馈 | 检查来自冻结验收集合，已有失败已确认 |
| `replan` | 进入现有受限规划／流程升级路径 | 当前任务允许规划，保留范围、修订次数与历史 |
| `model-N` | 选择允许集合中的具体执行配置 | 已配置 `execution-policy`，完整绑定与切换次数符合规则 |

`N` 是冻结候选集合的索引，不是模型名称或自定义命令。模型候选解析成实际
绑定 ID、harness、Provider、账号渠道、模型、effort、权限与会话
策略；没有批准候选时不猜测模型名称，也不增加付费渠道。模型／effort 改变继续
使用已有冷启动规则，不把执行者会话交给 Reviewer。AUTH／QUOTA 等渠道问题仍走
对应后备规则，不被当成模型推理能力不足。允许集配置见[配置参考](configuration.md)。

短反馈检查的 `purpose` 是 1–160 字符的非空白用途说明；JEV 候选发送该说明，
不附加 `cmd`／`script` 文本。说明本身也不要填写密钥、原日志或命令文本。
没有 `purpose` 的条目仍可供 Executor 参考，但不进入 JEV
定向选择候选。`purpose` 仅属于 `feedback-checks`，不会扩展验收字段或授权范围。

反馈检查只为下一次行动提供证据。即使某项检查已经通过，最终仍在当前候选上运行
全部必需验收；不能以这一次选择删除检查。桌面在任务与节点中显示决策请求、采用
或基线原因、反馈检查和实际效果。`applied` 表示控制决策已经应用，后续修复、
规划或新模型会话仍以节点记录为准；`completed` 表示该次控制动作已经收尾，
不代表整个任务已交付。`feedback-completed` 也只是反馈检查收尾。
`pending` 需要核对请求；`feedback-running`、`feedback-unknown` 需要核对原执行，
不能自动重放。`feedback-stale` 表示反馈改变了候选或验证输入，流程已阻断。
`replan-running` 表示重规划尚未收尾，恢复时须核对原 Plan 会话，不能再次派发来
猜测前一次的结果。
已采用的模型切换另列实际绑定前后值、尝试次数、原因和时间；不能从 `model-N`
猜测实际模型，也不能把配置切换当成新会话已经成功运行。

## 数据、预算与恢复

每轮调查获得授权并创建记录时，Go 冻结有效 JEV 后端、完整解析目标、数据类别、阈值和调用预算。任务输入中
旧的 `decision` 模式不能绕过关闭的总开关。启用后的默认数据集合允许任务摘要、
诊断假设、结构化命令／HTTP 结果，以及已批准文件取证的有界片段；可通过
`allowed-data` 缩小范围。原命令／HTTP 输出只有明确允许 `logs` 时才附加，否则
标记原内容缺失并使用结构化事实。数据范围不等同自动脱敏：若其余快照仍包含
未授权类别，请求整体跳过，不能借摘要绕过原有数据权限。

运行中关闭总开关，会停止后续 JEV 请求及建议采用，包括开关关闭后才返回的结果。
已经派发的请求仍按原身份核对，保留已知或未知用量，未知请求不重发。结果未知的
**实际动作**仍阻断执行，不能借切换开关绕过。

创建时关闭的调查轮次继续基线路径，后续开启不会改写这一轮；用户明确授权的新轮次
可以冻结新策略，仍受同一累计剩余额度限制。

实施阶段在已启用的运行中，首次符合条件的首轮选择或失败处冻结自己的运行时决策策略。
如果当前进程启动时 JEV 关闭，且尚无运行时决策账本，仅保存开启设置不会立即
启用该进程；须启动或恢复任务，读取已开启的配置。已有运行时决策账本时，关闭
再开启仍保留冻结目标、记录和剩余额度，包括调查导入的次数。修改目标或收紧
权限、限制，使当前配置与冻结策略不再相容时，停止后续可选决策，不偷偷重写策略。
查看界面中的 JEV 状态和原因，不复制账本、重置预算来重新派发。

`max-calls` 是每项任务的调用上限，包括已派发但结果未知的请求。调查移交实施时，
历轮已使用的次数全部计入实施额度；多个 packet、模型切换、重规划和恢复不能重新获得完整
额度。这个限制不等于 token 或金额上限。配置了硬预算而服务无法强制单次消耗上限
时，跳过 JEV。请求记录服务实际返回的用量，缺失保持 unknown。原生会话累计计数
不当作每次调用增量重复入账；使用订阅不记作费用为零。返回的概率与适用性是未校准的
模型估计，不是实测正确率。

订阅适配器先持久化关联的 lifecycle checkpoint，再确认派发。崩溃、中断或缺失终态
都不能触发新 prompt。恢复只查询原生 supervisor 的原始 journal；若能证明进程回收，
另存 `*.reconciled.json` 补充这一事实，保留原 unknown 回执、未知用量和确定性基线，
不会迟到采用模型答案。证明不足时，关闭 JEV、提交报告、新增调查轮次或切模型，都不能
绕过进程回收阻断。

实施阶段的 `runtime-decisions` 位于 `state.json`，记录冻结策略、已用次数、
调查导入次数和逐项请求／选择／效果，沿用已有 state 提交与交付规则。私有且排除
自动交付的是 `.investigation/runtime-decisions` 请求 journal；这个排除规则不
覆盖 `state.json` 中的决策信息副本。

桌面只展示有界摘要，投影移除原始快照和目标配置；这只限制桌面输出，不构成 Git
交付脱敏。批准的目标、事实、绑定和反馈输出仍与已有失败反馈一样，遵守不记录
凭据的规则。请求或动作尚未完成时，从原任务恢复核对，不能用新账本或切换模型
绕过未知结果。

## 离线回放与显式评估

正常任务在私有决策账本中保存冻结的 `*.input.json` 和回执。现有离线 System One
响应解析器也接受历史 HTTP `*.snapshot.json`：

```bash
flywheel decision replay --input frozen.input.json --response native-response.json \
  --endpoint "$JEV_ENDPOINT" --model jev-1.14.0 --expected-model jev-1.14.0
```

离线回放不读取密钥、不发请求、不写账本或任务状态。裸 Snapshot 需要
`--policy reviewed-policy.json`；显式策略完整替换原策略，不继承省略的数据权限。

需要实际在线评估时，先在相应范围开启 JEV：

```bash
flywheel decision evaluate --cwd "$repo_dir" --input frozen.input.json \
  --directory ./decision-evaluation --max-calls 5
```

后端和完整目标取自同一配置。订阅后端解析具名模型配置，不读取 API 密钥；显式模型
核对参数必须匹配，API 地址与密钥参数会被拒绝。旧 HTTP 目标参数必须与配置一致。评估
命令强制只建议，不执行动作、不改任务状态；其次数、超时、阈值和数据范围不能
放宽配置边界。同一输入和账本只读取原回执，未知请求不会重发。

两种工具都输出 `adopted: false`。在线错误或未知返回退出码 3，输入／配置错误
为 1，取消为 143。离线 fixture 通过不能证明真实模型成功率或任务加速。

## 显式旧 HTTP 配置

已有文件省略 backend 时保留旧 HTTP 契约；不启用全局 subscription-only 的配置也
可以明确使用 `backend: "http"`。它要求地址中不含凭据的 HTTPS `/v1/systemone`
endpoint、固定 `jev-x.y.z` 请求／响应版本和 `key-env` 变量名称。旧默认超时为
5000 ms，HTTP 明文地址仅允许本地回环测试。`key-env` 接受 1–120 位 ASCII 字母、
数字和下划线，首位为字母或下划线，保留大小写。进程接收密钥，配置只保存名称。
这是独立计费的集成，不是订阅自动后备；全局 subscription-only 会拒绝启用它。
旧 HTTP 目标哈希与冻结回执继续可读。

## 从影子功能迁移

旧自动观察器和独立影子请求客户端已经移除。旧 `jev-shadow` 配置仍可读取并迁移
连接信息，但旧开启值不会自动启用在线决策。明确的新 `jev` 配置优先。编辑器保存
统一配置并移除旧 key，保留原来的备份和 revision 检查。旧 `shadow` 命令只提示
迁移方式，不再执行实验；历史记录及其 schema 保留作证据。

评估实际价值时，对比开关关闭与开启的完整任务：获得有效证据的时间、执行／跳过
动作数、总耗时、实际与未知用量、最终质量。只改变顺序或通过离线 fixture，均不能
单独证明加速。
