# JEV 决策

[文档目录](../README.zh-CN.md) · [English](../en/jev.md) · 简体中文

Flywheel 只有一个 JEV 开关：**启用 JEV**（`jev.enabled`），默认关闭。
开启后，所有已支持的 JEV 决策点自动参与流程，不再分别设置影子、建议、采用或
分功能开关。

## 配置一次，继续使用原来的入口

桌面进入 **Flywheel → 配置 → JEV 决策**，选择需要的全局或项目范围，填写
System One 地址、固定版本模型和密钥环境变量名，打开 JEV 并保存。执行 Flywheel
的进程需要继承该环境变量；配置只保存变量名称，不保存密钥值。保存就是启用操作，
后续任务不为同一设置重复询问。高级字段限定超时、调用次数、阈值和发送数据类别。

等价配置片段：

```json
{
  "jev": {
    "enabled": true,
    "endpoint": "https://your-service.example/v1/systemone",
    "model": "jev-1.14.0",
    "key-env": "MEROUTER_API_KEY",
    "timeout-ms": 5000,
    "max-calls": 8,
    "min-applicability": 0.8,
    "min-choice": 0.6,
    "allowed-data": ["task-summary", "diagnostic-facts", "source"]
  }
}
```

把示例地址替换为实际服务地址。模型必须固定为 `jev-x.y.z`，并与响应版本匹配。
分发模板的地址为空、开关关闭；开启但目标配置非法时，配置校验失败。运行时缺少
凭据则记录跳过原因并继续原有确定性路径。

配置按**任务 → 项目 → 全局 → 内嵌表选择一份完整文件**，不跨文件深合并。项目
配置中的关闭会覆盖全局开启。通过 `config inspect --cwd <项目> --task-dir <任务>
--json` 查看实际配置来源；详见[配置参考](configuration.md)。

配置好以后照常使用：

- **Task**：从目标准备并运行已授权的调查。Go 自动解析 JEV 策略，宿主不再手写决策模式。
- **New**：准备同一调查契约后停下，等待用户要求运行。
- **Run**：在原目录启动或恢复已准备的调查。
- **Auto、Quick、Full**：仍是实现工作流策略；适用资格、验收和 review 由 Go 执行。

## 一个开关控制哪些路径

| 决策点 | 开启 JEV | 关闭 JEV |
| --- | --- | --- |
| 下一项取证动作 | 有不确定性时，在已批准的读取、搜索、目录列举动作中选择 | 原有确定性顺序 |
| 重复取证 | 通过绑定实际观察的控制选项，跳过已经取证的假设所对应的冗余动作 | 保留原动作集 |
| 是否进入报告 | 满足引擎证据前提时，可以提前结束收集 | 按原动作、时间、输出预算结束 |
| 显式在线评估 | 服从同一总开关、目标和配置边界 | 在创建评估账本或请求前拒绝 |
| 已有记录的离线回放 | 本地读取和解析，不调用模型 | 仍可查看，不调用模型 |

开启所有已支持的决策点，不等于每个任务都增加一次 JEV 调用。单一合法动作和
确定性选择直接执行。数据范围不允许、硬预算无法可靠约束单次消耗、次数耗尽、
适用性不足、服务错误或响应非法时，继续基线路径并保留原因。当前真实采用的动作
族是调查；协议中出现的修复、重新规划、模型选择枚举不代表这些功能已经接入。

提前结束和跳过动作只决定如何收集证据，不证明根因成立。Go 保存决策、观察和
动作的具体绑定；分析者仍须提交覆盖全部假设的报告，引用真实观察并说明不确定性。
没有结论仍是 inconclusive。后续修复须沿用原来的授权范围，完成实现、review 和
验证流程。详见[调查指南](investigation.md)。

## 数据、预算与恢复

创建准备记录时，Go 冻结有效 JEV 目标、数据类别、阈值和调用预算。任务输入中
旧的 `decision` 模式不能绕过关闭的总开关。启用后的默认数据集合允许任务摘要、
诊断假设，以及已批准取证结果的有界片段；可通过 `allowed-data` 缩小范围。
数据范围不等同自动脱敏：快照含有未授权类别时，整个请求跳过。

运行中关闭总开关，会停止后续 JEV 请求及建议采用，包括开关关闭后才返回的结果。
已经派发的请求仍按原身份核对，保留已知或未知用量，未知请求不重发。结果未知的
**实际动作**仍阻断执行，不能借切换开关绕过。

重新开启原本启用 JEV 的运行，会沿用原目标、账本和剩余预算。创建时关闭的准备
记录，在该次运行中继续基线路径；新准备记录才获得新开启的策略。修改目标或收紧
权限、限制，使旧运行与冻结策略不再相容时，该运行停止可选决策，不偷偷重写契约。
查看界面中的 JEV 状态和原因，不复制账本、重置预算来重新派发。

`max-calls` 包括已派发但结果未知的请求。这是次数上限，不能冒充 token 或金额
上限。配置了硬预算而服务无法强制单次消耗上限时，跳过 JEV。请求记录服务实际
返回的用量，缺失保持 unknown。

## 离线回放与显式评估

正常任务在私有决策账本中保存冻结的 `*.input.json` 和回执。离线回放也接受历史
`*.snapshot.json`：

```bash
flywheel decision replay --input frozen.input.json --response native-response.json \
  --endpoint "$JEV_ENDPOINT" --model jev-1.14.0 --expected-model jev-1.14.0
```

离线回放不读取密钥、不发请求、不写账本或任务状态。裸 Snapshot 需要
`--policy reviewed-policy.json`；显式策略完整替换原策略，不继承省略的数据权限。

需要实际在线评估时，先在相应范围开启 JEV：

```bash
flywheel decision evaluate --cwd "$repo_dir" --input frozen.input.json \
  --directory ./decision-evaluation --max-calls 5
```

目标、固定模型和密钥变量取自同一配置；旧的显式目标参数必须与配置一致。评估
命令强制只建议，不执行动作、不改任务状态；其次数、超时、阈值和数据范围不能
放宽配置边界。同一输入和账本只读取原回执，未知请求不会重发。

两种工具都输出 `adopted: false`。在线错误或未知返回退出码 3，输入／配置错误
为 1，取消为 143。离线 fixture 通过不能证明真实模型成功率或任务加速。

## 从影子功能迁移

旧自动观察器和独立影子请求客户端已经移除。旧 `jev-shadow` 配置仍可读取并迁移
连接信息，但旧开启值不会自动启用在线决策。明确的新 `jev` 配置优先。编辑器保存
统一配置并移除旧 key，保留原来的备份和 revision 检查。旧 `shadow` 命令只提示
迁移方式，不再执行实验；历史记录及其 schema 保留作证据。

评估实际价值时，对比开关关闭与开启的完整任务：获得有效证据的时间、执行／跳过
动作数、总耗时、实际与未知用量、最终质量。只改变顺序或通过离线 fixture，均不能
单独证明加速。
